Workflow

  • 1 Problem first Define what the tool does before writing any code. No gold-plating, no features that aren't needed yet.
  • 2 Terminal & vim Write code in vim, run it in bash. No IDE overhead. Fast feedback loop.
  • 3 Security by default Validate input at boundaries, use parameterized queries, apply CSP, run with least privilege. Baked in from the start, not bolted on.
  • 4 Ship the CLI first Build the core logic as a standalone CLI. Web UI is layered on top. The tool works without a browser.
  • 5 git & feature branches Every change on its own branch. Clear commit messages. No force-pushing, no skipping hooks.
  • 6 Iterate on real constraints Mobile perf for Lens Studio, network latency for DNS tools, no-backend for static sites. Real constraints drive real decisions.

Security posture

Least privilege by default. Tools run with the minimum permissions needed. Scripts don't request root unless unavoidable. Web pages request no permissions at all.
Input validation at every boundary. Email addresses validated against a strict RFC-5321 regex before any DNS lookup. No user input reaches DNS queries unsanitized.
No eval, no innerHTML with untrusted data. The web UI builds the DOM with textContent and safe element creation. CSP blocks inline scripts.
secrets over random. Any token or password generation uses Python's secrets module, never the statistically predictable random.
OSINT tools require authorization. email-info is documented as authorized-testing-only. The disclaimer is in the source, the README, and the web UI.
Zero external dependencies on static pages. No CDN scripts, no analytics, no tracking pixels. Everything self-hosted or inline.
