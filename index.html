Readability and structure

Use clear names, small functions, and type hints where they help. Avoid magic numbers and deep nesting. Return early to reduce complexity.

# Prefer
def is_valid_user(user_id: int, min_age: int = 18) -> bool:
    return get_user(user_id).age >= min_age

# Avoid
def check(u):
    return get_user(u).age >= 18

Data structures

Lists for ordered sequences, dicts for key-value, sets for uniqueness. Use defaultdict or Counter when they fit.

from collections import Counter
counts = Counter(line.split()[0] for line in log_lines)  # e.g. IP counts

Functions

Single responsibility. Keyword-only args for clarity. Use secrets for tokens and passwords, not random.

import secrets
token = secrets.token_urlsafe(32)

Common mistakes

Mutable default: def f(x=[]): reuses the same list. Use def f(x=None): x = x or [].
SQL: Never build SQL with f-strings. Use parameterized queries.
Secrets: Use secrets for anything security-sensitive; random is not cryptographically secure.

Cybersecurity Awareness

High-level concepts so you can reason about threats and defenses. Focus on understanding, not fear. Below is static placeholder news — no live API.

Concepts that matter

Input validation: Validate and sanitize all input. Assume untrusted data until proven otherwise.

Least privilege: Run with the minimum permissions needed. Same for users and services.

Defense in depth: Don’t rely on one control. Use multiple layers (headers, auth, validation, logging).

Supply chain attack via typosquatted PyPI packages

Malicious packages with names similar to popular ones were uploaded to PyPI. Install scripts ran unwanted code or exfiltrated environment variables.

Low

Security headers missing on many APIs

Widespread omission of CSP, HSTS, and X-Frame-Options on public APIs increases XSS and clickjacking surface.

Why it matters: Add security headers in your API or gateway. Use a checklist for every new endpoint.

Security

This section explains the security posture of this site and what is in scope for a frontend-only, static page.

Threat modeling (basics)

Assets: Static content, no user data. No login, no backend, no database.

Threats in scope: XSS (mitigated by no user-controlled DOM injection and CSP), clickjacking (CSP frame-ancestors 'none'), MIME sniffing (server should send X-Content-Type-Options: nosniff), referrer leakage (meta Referrer-Policy).

Out of scope here: Server compromise, authentication, authorization, injection into a backend, database access, session handling. Those belong on the server and are not implemented in this file.

Why frontend security still matters

Even without a backend, a page can be embedded in a hostile site (clickjacking), or a compromised CDN could inject scripts. CSP and strict defaults reduce the impact of injection and prevent embedding. Referrer policy limits what third-party sites learn when users follow links. These are defensive defaults.

What this page does

  • Content-Security-Policy (meta): default-src 'self'; scripts and resources from same origin only. style-src 'unsafe-inline' only because this is a single file with one embedded stylesheet. frame-ancestors 'none' to block embedding. base-uri 'self' to prevent base-tag injection.
  • Referrer-Policy (meta): strict-origin-when-cross-origin so full URL is not sent to other origins.
  • No inline scripts: No eval, no dynamic script injection. No JavaScript at all on this page; any future script would require justification and must avoid eval and innerHTML with unsanitized data.
  • No external scripts, trackers, or analytics: Zero third-party JS or tracking.
  • External links: One outbound link (Snapchat) with rel="noopener noreferrer" to avoid tab-napping and limit referrer.

Server responsibilities (not in this file)

When you serve this HTML over HTTP(S), the server should send: X-Content-Type-Options: nosniff, X-Frame-Options: DENY (or rely on CSP frame-ancestors), Permissions-Policy to disable unneeded features, and Strict-Transport-Security if using HTTPS. This file cannot set those; configure the web server or reverse proxy.
